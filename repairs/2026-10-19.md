## 監控與保護

- 九個固定 BVID 追蹤分 P；九個 UP 規則追蹤同作品的新單集 BVID。
- UP 搜尋以作品關鍵字分開查詢及快取，避免高產 UP 的其他作品擠掉最近 30 筆。
- 搜尋 API 實測會混入其他 UP 的推薦，先檢查 `upMid`；無可靠身分時不可用猜測的 UP 身分做 pagelist fallback。
- 新 UP 規則只接收帶明確集數的單集，已知合集則逐 P 檢查。短片、PV、先行圖及「更新中／周更」佔位內容不算已播集數。
- 新番每 P 要有明確集數和至少 900 秒片長，暗黑召喚師為 600 秒。片長只是排除明顯短片，不代表已逐幀驗證內容。
- 合集與 UP 新 BV 雙向按集數去重；CID 換檔不重貼。
- 首文建立後立即保存 thread_id，讀回確認成功才寫入已發集數，避免讀回失敗時另開重複串。
- 保留原本七天未更新警報；來源查詢失敗不當作成功檢查。

## 驗證界線

- B 站搜尋頁及公開影片 metadata 核對標題、UP、分 P、集數與片長；未下載或逐幀觀看，未宣稱 4K／無刪減或永久可播放。
- 本機 view API 仍有 HTTP 412，公開影片 HTML / 已驗證來源的 pagelist fallback 成功，沒有要求或搬移瀏覽器 Cookie。
- 雲端定時流程仍依賴 B 站來源與 Discord 可用性；來源刪除、更名或 UP 改帳號不能保證自動找到任意替代來源。
- `bilibili_enroll.py` 僅供人工明確授權的初始建立，不加入自動排程。執行前必須確認 C炭服務正在運作，Token 只從現有服務環境傳入，禁止寫入計畫檔或 GitHub。
